# Central ECU, RTOS 포팅 및 시스템 구조 변경 (V2.0.0)

**RTOS 도입의 필요성: 비동기 이벤트 처리와 실시간성 확보**

기존의 순차적 `while(1)` 루프 구조는 조종기로부터의 RF 통신과 차량 내부 ECU로부터의 CAN 통신이라는 두 가지 비동기적 이벤트를 동시에 처리하는 데 한계가 있었다. 하나의 이벤트를 처리하는 동안 다른 이벤트의 처리가 지연되어 차량 제어의 실시간성을 보장하기 어려웠다.

본 Central ECU는 조종기의 주행 명령을 즉각적으로 모터에 반영하는 동시에, 센서 ECU로부터 수신되는 데이터를 처리하여 다시 조종기로 피드백해야 한다. 이러한 복합적인 요구사항을 안정적으로 만족시키기 위해 FreeRTOS를 도입하여 멀티태스킹 시스템으로 전환했다.

## main.c : RTOS 도입에 따른 구조적 변화
FreeRTOS가 적용되면서 main.c는 어플리케이션의 메인 루프가 아닌, 시스템을 부팅하고 RTOS 스케줄러에 제어권을 넘기는 시스템 로더(Loader) 로 역할이 변경되었다.

1. main() 함수의 역할 축소

- 초기화 전담: main() 함수는 하드웨어(HAL_Init, MX_..._Init), 커스텀 모듈(RFHandler_Init, CANHandler_Init, MotorControl_Init), RTOS 커널(osKernelInitialize)을 순서대로 초기화한다.
- 스케줄러 시작: osKernelStart() 함수를 호출하여 모든 제어권을 FreeRTOS 스케줄러로 넘긴다. 이 시점 이후 main()의 while(1) 루프는 더 이상 실행되지 않는 **데드 코드(Dead Code)**가 된다.

2. 인터럽트 처리 방식 변경: Flag에서 Semaphore로

- 기존 방식 (Polling): RF 수신 인터럽트(IRQ) 발생 시 콜백 함수가 플래그 변수를 1로 만들고, 메인 루프가 이 플래그를 계속 확인하는 비효율적인 구조였다.
- RTOS 방식 (Event-Driven): HAL_GPIO_EXTI_Callback 함수는 이제 플래그 대신 **세마포어(RFSemHandle)**를 **해제(Release)**한다. 이 신호는 RF 수신을 기다리며 잠들어 있던 RFTask를 즉시 깨워, CPU 낭비 없이 신속한 이벤트 처리가 가능해졌다.

```c
// main.c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_3)  // IRQ 핀
    {
        RFHandler_IrqCallback(); // 핸들러에게 위임
    }
}

// rf_handler.c
void RFHandler_IrqCallback(void)
{
    if (osKernelGetState() == osKernelRunning && RFSemHandle) {
        (void)osSemaphoreRelease(RFSemHandle); // 세마포어를 해제하여 대기중인 RFTask를 깨움
    }
}
```

3. 어플리케이션 로직의 완전한 태스크 분리

- 기존 main()에 혼재되어 있던 모든 로직은 이제 RFTask와 CANTask라는 독립된 RTOS 태스크로 완전히 분리 및 이관되었다.

## freertos.c : 멀티태스킹 시스템의 구현

freertos.c는 Central ECU의 핵심 로직을 담고 있다. 각 기능은 독립적인 **태스크(Task)**로 분리되어 실시간성과 안정성을 확보한다.

1. RTOS 객체 생성 (MX_FREERTOS_Init)
- **태스크 (Threads)**
    - RFTask (높은 우선순위): 조종기 RF 명령을 수신, 해석하여 모터를 제어하고, CAN 통신 결과를 조종기로 피드백하는 핵심 제어 태스크.
    - CANTask (보통 우선순위): RFTask로부터 받은 차량 상태를 CAN 버스를 통해 다른 ECU로 전파하는 게이트웨이 태스크.

- **메시지 큐 (Message Queues)**
    - CANTxQueueHandle: RFTask가 처리한 주행 명령과 상태를 CANTask로 전달하는 통신 채널. RFTask의 제어 로직과 CANTask의 전송 로직을 분리(Decoupling)한다.
    - CANRxQueueHandle: CAN 수신 인터럽트(ISR)가 센서 ECU로부터 받은 데이터(RPM, 장애물 정보)를 RFTask로 안전하게 전달하는 통신 채널.

- **세마포어 (Semaphore)**
    - RFSemHandle: RF 수신 인터럽트(ISR)와 RFTask 사이의 동기화를 위한 신호. IRQ 발생 시 ISR이 세마포어를 반납하여 RFTask를 깨운다.

2. 태스크 우선순위 설계
- RFTask (High Priority): 사용자 조작에 직접 반응하고 차량을 구동하는 가장 핵심적인 태스크이므로, 다른 작업에 의해 실행이 방해받지 않도록 가장 높은 우선순위를 부여했다.

- CANTask (Normal Priority): 차량 상태를 외부에 알리는 역할을 하며, 제어 자체보다 시간 제약이 덜 엄격하므로 보통 우선순위로 설정했다.

3. 태스크 구현

`StartRFTask` (총괄 제어기)
- osSemaphoreAcquire()를 통해 RF 수신 이벤트(RFSemHandle)가 발생할 때까지 대기하며, 250ms 타임아웃을 두어 통신 두절 상태를 감지한다.

- 이벤트 발생 시 CANRxQueue에서 최신 센서 데이터를 확인하여 조종기로 보낼 ACK 페이로드를 준비한다.
- RFHandler_GetNewCommand()로 실제 주행 명령을 받아 MotorControl_Update()를 호출하여 차량을 제어하고, osMessageQueuePut()으로 해당 상태를 CANTask에 전달한다.

```c
void StartRFTask(void *argument)
{
    // ...
    for(;;)
    {
        // 1. RF 수신 인터럽트를 타임아웃과 함께 대기
        if (osSemaphoreAcquire(RFSemHandle, RF_SEMAPHORE_TIMEOUT) == osOK)
        {
            // 2. CAN 수신 큐에서 ACK에 실을 데이터 확인
            if (osMessageQueueGet(CANRxQueueHandle, &received_can_packet, NULL, 0U) == osOK) {
                // ... ACK 페이로드 준비
            }
            
            // 3. RF 명령 수신 및 처리
            while (RFHandler_GetNewCommand(&cmd)) {
                // 4. 모터 제어 업데이트
                MotorControl_Update(&cmd);
                // 5. CAN 전송을 위해 큐에 데이터 삽입
                osMessageQueuePut(CANTxQueueHandle, &cmd, 0U, 0U);
                // 6. 다음 ACK 페이로드 설정
                RFHandler_SetAckPayload(ack_payload, sizeof(ack_payload));
            }
        } else {
            // RF 신호 수신 타임아웃 (실패) 처리
        }
    }
}
```

`StartCANTask` (상태 전파 게이트웨이)
- osMessageQueueGet()를 통해 CANTxQueueHandle에 새로운 데이터가 들어올 때까지 무한정 대기한다.
- RFTask로부터 주행 상태를 수신하면, CAN_Send_DriveStatus()를 호출하여 방향, 브레이크, RF 상태를 CAN 버스로 브로드캐스팅한다.

```c
void StartCANTask(void *argument)
{
    VehicleCommand_t received_cmd;
    for(;;)
    {
        // 1. 큐에서 VehicleCommand_t 구조체 수신 대기
        osMessageQueueGet(CANTxQueueHandle, &received_cmd, NULL, osWaitForever);

        // 2. 수신한 데이터에서 필요 정보 추출
        uint8_t dir = received_cmd.direction;
        uint8_t brake = (received_cmd.brake_ms > 0) ? 1 : 0;
        bool rf_ok = received_cmd.rf_status;

        // 3. 실제 CAN 전송 함수 호출
        CAN_Send_DriveStatus(dir, brake, rf_ok);
    }
}

```
