# 컨트롤러부 디스플레이 태스크 및 전/후진, RPM OLED 출력 로직 추가 (v2.1.0)

## 동작 요약
v2.1.0 버전에서는 사용자 경험 향상을 위해 OLED 디스플레이를 제어하는 전용 FreeRTOS 태스크(`DisplayTask`)를 추가했다. 이 태스크는 조종기와 RC카의 상태를 실시간으로 시각화하는 역할을 담당한다.

주요 기능으로, RC카로부터 수신하는 ACK Payload에 포함된 RPM 데이터를 기반으로 현재 속도를 백분율(%)로 표시한다. 또한, 사용자가 조작하는 토글 스위치의 상태를 감지하여 현재 기어를 전진(D) 또는 후진(R)으로 화면에 출력한다. 통신이 끊길 경우에는 "NO SIGNAL" 메시지를 표시하여 즉각적인 피드백을 제공한다. 이 모든 디스플레이 로직은 다른 제어 및 통신 태스크와 독립적으로 동작하여 시스템 안정성을 확보했다.

## 코드 주요 로직
1. DisplayTask 생성 및 실행 (`freertos.c`)
OLED 디스플레이의 모든 업데이트를 전담하는 DisplayTask를 새로운 FreeRTOS 태스크로 생성했다. 이 태스크는 다른 기능에 영향을 주지 않고 독립적으로, 주기적으로 화면을 갱신하는 역할만 수행한다.

```c
// freertos.c

// DisplayTask 핸들 및 속성 정의
osThreadId_t DisplayTaskHandle;
const osThreadAttr_t DisplayTask_attributes = {
  .name = "DisplayTask",
  .stack_size = 256 * 4,
  .priority = (osPriority_t) osPriorityNormal,
};

void MX_FREERTOS_Init(void) {
  /* ... 다른 태스크, 큐, 세마포어 생성 ... */

  // DisplayTask 생성
  DisplayTaskHandle = osThreadNew(StartDisplayTask, NULL, &DisplayTask_attributes);
}
```

2. DisplayTask 구현: 데이터 시각화 로직 (freertos.c)
StartDisplayTask 함수는 무한 루프 내에서 공유 데이터(g_displayData)를 안전하게 읽어와 OLED 화면에 표시하는 로직을 수행한다.

데이터 처리: ackHandlerTask로부터 업데이트된 RPM 값과 토글 스위치 기반의 주행 방향(direction) 값을 localDisplayData 변수에 복사한다.

RPM 시각화: 수신된 RPM 값을 최대 RPM 대비 백분율로 변환하고((int)(((float)localDisplayData.rpm / MAX_RPM) * 100.0f)), sprintf 함수를 이용해 문자열로 만들어 출력한다.

기어(D/R) 표시: direction 값에 따라 "D"(전진) 또는 "R"(후진) 문자열을 선택하여 화면에 표시한다.

```c
// freertos.c

/* USER CODE BEGIN Header_StartDisplayTask */
/**
* @brief Function implementing the DisplayTask thread.
* @param argument: Not used
* @retval None
*/
/* USER CODE END Header_StartDisplayTask */
void StartDisplayTask(void *argument)
{
  /* USER CODE BEGIN StartDisplayTask */
   DisplayData_t localDisplayData = {0}; // 화면에 표시할 데이터의 로컬 복사본
   char speed_str[16];
   char dir_str[10];
   int speed_percentage;

   /* Infinite loop */
   for(;;)
   {
	 // 1. 뮤텍스로 보호된 공유 데이터(g_displayData)를 안전하게 복사
	 if (osMutexAcquire(g_displayDataMutexHandle, osWaitForever) == osOK)
	 {
		 localDisplayData = g_displayData;
		 osMutexRelease(g_displayDataMutexHandle);
	 }

	 SSD1306_Fill(SSD1306_COLOR_BLACK); // 화면 초기화

	 // 2. 통신 상태 확인
	 if (localDisplayData.comm_ok)
	 {
		 // --- 통신 정상: RPM과 기어 상태 표시 ---
		 // RPM을 백분율로 변환
		 speed_percentage = (int)(((float)localDisplayData.rpm / MAX_RPM) * 100.0f);
		 if (speed_percentage > 100) { speed_percentage = 100; }
		 sprintf(speed_str, "%d %%", speed_percentage);

		 // 방향(Direction)에 따라 D 또는 R 문자열 선택
		 switch(localDisplayData.direction)
		 {
			 case 0: strcpy(dir_str, "   R"); break; // 후진
			 case 1: strcpy(dir_str, "   D"); break; // 전진
			 default: strcpy(dir_str, ""); break;
		 }

		 // 화면에 기어와 속도 문자열 출력
		 SSD1306_Puts(dir_str, &Font_11x18, 1);
		 SSD1306_GotoXY(39, 20);
		 SSD1306_Puts("SPEED", &Font_11x18, 1);
		 /* ... */
		 SSD1306_Puts(speed_str, &Font_11x18, 1);
	 }
	 else
	 {
		 // --- 통신 실패: "NO SIGNAL" 메시지 표시 ---
		 SSD1306_GotoXY(5, 25);
		 SSD1306_Puts("NO SIGNAL", &Font_11x18, 1);
	 }

	 SSD1306_UpdateScreen(); // 화면 전체 업데이트

	 osDelay(DISPLAY_TASK_PERIOD_MS); // 주기적인 업데이트를 위해 딜레이
   }
  /* USER CODE END StartDisplayTask */
}
```

## 문제 및 해결

### 문제점 : Race Condition (경쟁 상태)
새로운 DisplayTask가 화면에 데이터를 출력하기 위해 g_displayData를 읽는 동시에, 통신을 담당하는 ackHandlerTask가 새로운 ACK Payload 데이터로 g_displayData를 수정할 경우 데이터가 깨지거나 일관성이 없는 정보가 화면에 표시될 수 있다.

### 해결 방안 : Mutex (뮤텍스) 도입
g_displayData를 공유 자원으로 지정하고, 이 자원에 접근하는 모든 코드 블록을 FreeRTOS의 Mutex로 보호했다. DisplayTask와 ackHandlerTask는 g_displayData에 접근하기 전 반드시 osMutexAcquire()를 통해 잠금을 획득해야 하며, 접근이 끝나면 osMutexRelease()로 잠금을 해제해야 한다. 이를 통해 한 번에 하나의 태스크만 공유 데이터에 접근하도록 보장하여 데이터 무결성을 확보했다.

## 향후 확장 아이디어

- 상세 텔레메트리 표시: 현재 RPM만 표시하지만, ACK Payload에 차량의 배터리 전압, 모터 온도 등을 추가하여 OLED 화면에 함께 표시.

- 그래픽 UI 도입: 텍스트 기반의 현재 UI를 개선하여, 속도를 게이지 바 형태로 표시하거나 배터리 잔량을 아이콘으로 시각화하여 직관성을 높임.

- 설정 메뉴 추가: 디스플레이가 추가되었으므로, 특정 버튼 조합으로 설정 모드에 진입하여 조향 감도, 최대 속도 제한 등의 파라미터를 OLED 화면을 보며 직접 수정하고 저장하는 기능 구현.
