# Status ECU, RTOS 포팅 및 시스템 구조 변경 (V2.0.0)

**RTOS 도입의 필요성: 비동기 데이터 처리와 안정적인 상태 표시**

기존의 순차적 `while`(1) 루프 구조는 여러 ECU로부터 비동기적으로 수신되는 CAN 통신 데이터 스트림을 처리하는 동시에, ADC를 통한 배터리 모니터링 및 I2C 기반의 OLED 디스플레이 업데이트와 같은 내부 작업을 수행하는 데 한계가 있었다. 특히, 디스플레이 업데이트와 같이 상대적으로 느린 작업을 처리하는 동안 CAN 메시지를 놓치거나, 반대로 CAN 메시지 폭주 시 디스플레이가 멈추는 현상이 발생할 수 있어 시스템의 안정성을 보장하기 어려웠다.

본 Status 부는 차량의 모든 상태 정보가 집결되는 허브이자, 사용자에게 최종 피드백을 제공하는 중요한 역할을 한다. 여러 비동기 이벤트를 안정적으로 처리하고 각 기능의 독립성을 보장하기 위해 FreeRTOS를 도입하여 멀티태스킹 시스템으로 전환했다.

## main.c : RTOS 도입에 따른 구조적 변화

FreeRTOS가 적용되면서 main.c는 어플리케이션의 메인 루프가 아닌, 시스템을 부팅하고 RTOS 스케줄러에 제어권을 넘기는 **시스템 로더(Loader)**로 역할이 변경되었다.

1. main() 함수의 역할 축소
- 초기화 전담: main() 함수는 하드웨어(HAL_Init, MX_..._Init), 커스텀 모듈(OLED_Init), RTOS 커널(osKernelInitialize)을 순서대로 초기화한다.

- 스케줄러 시작: osKernelStart() 함수를 호출하여 모든 제어권을 FreeRTOS 스케줄러로 넘긴다. 이 시점 이후 main()의 while(1) 루프는 더 이상 실행되지 않는 **데드 코드(Dead Code)**가 된다.

2. 인터럽트 처리 방식 변경: Polling에서 Message Queue로

- 기존 방식 (Polling): main 루프가 주기적으로 CAN 수신 버퍼를 확인하거나, Flag 변수를 통해 수신 여부를 확인하는 비효율적인 구조였다.

- RTOS 방식 (Event-Driven): CAN 메시지 수신 인터럽트(ISR)는 이제 HAL_CAN_RxFifo1MsgPendingCallback 함수 내에서 수신된 데이터를 **메시지 큐(CANRxQueueHandle)**에 직접 삽입한다. 이 데이터는 CAN 메시지 처리를 기다리며 잠들어 있던 CANTask를 즉시 깨우는 신호 역할을 하여, CPU 낭비 없이 신속한 이벤트 처리가 가능해졌다.

```c
// can_handler.c
void HAL_CAN_RxFifo1MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    CAN_RxPacket_t rxPacket;

    // CAN 하드웨어 버퍼에서 메시지를 읽어옴
    if (HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO1, &rxPacket.header, rxPacket.data) == HAL_OK)
    {
        // 읽어온 메시지를 메시지 큐에 전송하여 CANTask가 처리하도록 함
        if (CANRxQueueHandle != NULL)
        {
            osMessageQueuePut(CANRxQueueHandle, &rxPacket, 0U, 0U);
        }
    }
}
```

3. 어플리케이션 로직의 완전한 태스크 분리
- 기존 main()에 혼재되어 있던 모든 로직(CAN 데이터 분석, 배터리 측정, LED 제어, OLED 출력)은 이제 CANTask와 DisplayTask라는 독립된 RTOS 태스크로 완전히 분리 및 이관되었다.

## freertos.c : 멀티태스킹 시스템의 구현
freertos.c는 Status 부의 핵심 로직을 담고 있다. 각 기능은 독립적인 **태스크(Task)**로 분리되어 실시간 데이터 처리 능력과 시스템 안정성을 확보한다.

1. RTOS 객체 생성 (MX_FREERTOS_Init)
- **태스크 (Threads)**

    - CANTask (높은 우선순위): CAN 버스로부터 모든 ECU의 상태 데이터를 수신, 분석하고 통신 상태를 진단하는 핵심 데이터 처리 태스크.

    - DisplayTask (보통 우선순위): CANTask가 처리한 최종 데이터를 기반으로 LED와 OLED 디스플레이를 제어하는 사용자 인터페이스 태스크.

- **메시지 큐 (Message Queues)**

- CANRxQueueHandle: CAN 수신 인터럽트(ISR)가 외부 ECU로부터 받은 데이터를 CANTask로 안전하게 전달하는 통신 채널.

- DisplayDataQueueHandle: CANTask가 처리 및 진단을 마친 종합 상태 데이터를 DisplayTask로 전달하는 통신 채널. 데이터 처리 로직과 출력 로직을 완벽히 분리(Decoupling)한다.

2. 태스크 우선순위 설계
- CANTask (High Priority): 차량의 모든 상태 정보가 이 태스크를 통해 수집되므로, 데이터 손실 없이 실시간으로 처리하는 것이 가장 중요하다. 따라서 다른 작업에 의해 실행이 방해받지 않도록 가장 높은 우선순위를 부여했다.

- DisplayTask (Normal Priority): 사용자에게 상태를 보여주는 역할을 하며, 데이터 수집 자체보다 시간 제약이 덜 엄격하므로 보통 우선순위로 설정했다.

3. 태스크 구현
`StartCANTask` (데이터 수집 및 진단 게이트웨이)
- 20ms의 고정 주기로 동작하며, CANRxQueue에 쌓인 모든 메시지를 non-blocking으로 처리하여 항상 최신 상태를 유지한다.

- 메시지 수신 시간을 기록하여 각 ECU와의 통신이 250ms 이상 두절될 경우 타임아웃으로 진단한다.

- 분석된 차량 상태와 통신 진단 결과를 종합하여 DisplayDataQueue를 통해 DisplayTask에 전달한다.

```c
void StartCANTask(void *argument)
{
    // ...
    for(;;)
    {
        // 1. 20ms 주기로 동작
        osDelay(20);

        // 2. CAN 수신 큐의 모든 메시지를 처리하여 최신 상태로 업데이트
        while (osMessageQueueGet(CANRxQueueHandle, &rxPacket, NULL, 0) == osOK)
        {
            // ... CAN ID에 따라 데이터 파싱 및 타임스탬프 갱신 ...
        }

        // 3. 통신 타임아웃 진단
        uint32_t now = HAL_GetTick();
        displayData.is_central_can_ok = (now - g_last_rx_time_central) < CAN_TIMEOUT_MS;
        displayData.is_sensor_can_ok = (now - g_last_rx_time_sensor) < CAN_TIMEOUT_MS;

        // 4. 처리된 데이터를 DisplayTask로 전송
        osMessageQueuePut(DisplayDataQueueHandle, &displayData, 0, 0);
    }
}
```

`StartDisplayTask` (상태 출력 컨트롤러)
- osMessageQueueGet()을 통해 DisplayDataQueue에 새로운 데이터가 들어올 때까지 무한정 대기한다.

- 데이터 수신 즉시 LEDControl_Update()를 호출하여 차량의 주행 상태(전조등, 브레이크등)를 실시간으로 반영한다.

- 상대적으로 느린 I2C 통신을 사용하는 OLED 디스플레이는 50ms 주기로 업데이트를 제한하여, 시스템 부하를 줄이고 다른 태스크에 미치는 영향을 최소화한다.

```c
void StartDisplayTask(void *argument)
{
    DisplayData_t localData = {0};
    uint32_t last_oled_update_tick = 0;
    for(;;)
    {
        // 1. DisplayDataQueue에서 데이터 수신 대기
        if (osMessageQueueGet(DisplayDataQueueHandle, &localData, NULL, osWaitForever) == osOK)
        {
            // 2. LED는 즉시 업데이트하여 즉각적인 피드백 제공
            LEDControl_Update(localData.status_ldr, localData.status_direction, localData.status_brake);

            // 3. OLED는 50ms 주기로 업데이트하여 부하 분산
            uint32_t current_tick = HAL_GetTick();
            if (current_tick - last_oled_update_tick >= 50)
            {
                last_oled_update_tick = current_tick;
                // ... 배터리 측정 및 OLED_UpdateDisplay() 호출 ...
            }
        }
    }
}

```
