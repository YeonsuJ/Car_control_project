# Sensor ECU, RTOS 포팅 및 시스템 구조 변경 (V2.0.0)

**RTOS 도입의 필요성: 실시간 데이터 수집과 안정적인 전송 보장**

기존의 순차적 `while`(1) 루프 구조는 정밀한 주기로 센서 데이터를 수집하는 동시에, 수집된 데이터를 가공하여 CAN 버스로 전송하는 두 가지 주요 작업을 안정적으로 수행하는 데 한계가 있었습니다. 특히, RPM 계산과 같이 시간에 민감한 데이터 수집 작업이 CAN 전송 로직에 의해 지연(Jitter)되거나, 반대로 데이터 전송 중 다음 센싱 주기를 놓치는 문제가 발생할 수 있어 데이터의 신뢰성을 보장하기 어려웠습니다.

본 Sensor 보드는 차량의 물리적 상태를 감지하는 실시간 데이터 취득 허브로서, 모든 측정은 예측 가능한 시간 내에 이루어져야 합니다. 여러 센서의 독립적인 동작을 보장하고 데이터 수집과 전송 작업을 분리하여 시스템의 실시간성과 안정성을 확보하기 위해 FreeRTOS를 도입, 멀티태스킹 시스템으로 전환했습니다.

## main.c : RTOS 도입에 따른 구조적 변화

FreeRTOS가 적용되면서 main.c는 어플리케이션의 메인 루프가 아닌, 시스템을 부팅하고 RTOS 스케줄러에 제어권을 넘기는 **시스템 로더(Loader)**로 역할이 변경되었습니다.

1. main() 함수의 역할 축소

- 초기화 전담: main() 함수는 하드웨어(HAL_Init, MX_..._Init), 커스텀 모듈(DWT_Init), RTOS 커널(osKernelInitialize)을 순서대로 초기화합니다.

- 스케줄러 시작: osKernelStart() 함수를 호출하여 모든 제어권을 FreeRTOS 스케줄러로 넘깁니다. 이 시점 이후 main()의 while(1) 루프는 더 이상 실행되지 않는 **데드 코드(Dead Code)**가 됩니다.

2. 데이터 흐름 변경: 순차 처리에서 Message Queue 기반으로

- 기존 방식 (결합 구조): 단일 루프 안에서 센서 값을 읽고, 가공하고, 전송하는 모든 작업이 순차적으로 묶여 있어 한 작업의 지연이 다른 작업에 직접적인 영향을 미치는 구조였습니다.

- RTOS 방식 (분리 구조): SensorTask가 수집한 데이터를 **메시지 큐(CANTxQueueHandle)**에 삽입하면, 데이터 전송을 기다리며 잠들어 있던 CANTask가 즉시 깨어나 독립적으로 전송을 처리합니다. 이로써 데이터 수집과 전송이 완벽히 분리되어, SensorTask는 다른 작업에 방해받지 않고 정밀한 주기를 유지할 수 있습니다.

3. 어플리케이션 로직의 완전한 태스크 분리

- 기존 main()에 혼재되어 있던 모든 로직(초음파 트리거, RPM 계산, 데이터 패키징, CAN 전송)은 이제 SensorTask와 CANTask라는 독립된 RTOS 태스크로 완전히 분리 및 이관되었습니다.

## freertos.c : 멀티태스킹 시스템의 구현

freertos.c는 Sensor 보드의 핵심 로직을 담고 있습니다. 각 기능은 독립적인 **태스크(Task)**로 분리되어 실시간 데이터 처리 능력과 시스템 안정성을 확보합니다.

1. RTOS 객체 생성 (MX_FREERTOS_Init)

- 태스크 (Threads)

    - SensorTask (높은 우선순위): 10ms의 정밀한 주기로 초음파, 엔코더 등 모든 센서 데이터를 수집하고 1차 가공하는 핵심 데이터 생산 태스크.

    - CANTask (보통 우선순위): SensorTask가 전달한 데이터를 최종적으로 CAN 프로토콜에 맞게 가공하여 외부로 전송하는 데이터 소비자 태스크.

- 메시지 큐 (Message Queues)

    - CANTxQueueHandle: SensorTask가 생산한 종합 센서 데이터를 CANTask로 안전하게 전달하는 단방향 통신 채널. 데이터 생산 로직과 소비(전송) 로직을 완벽히 분리(Decoupling)합니다.

2. 태스크 우선순위 설계

- SensorTask (High Priority): 센서 데이터는 정해진 시간(10ms)에 정확하게 수집되어야 그 값이 유효합니다. 데이터 품질을 최우선으로 보장하기 위해 다른 작업에 의해 실행이 방해받지 않도록 가장 높은 우선순위를 부여했습니다.

- CANTask (Normal Priority): 데이터 전송은 수집된 이후에만 의미가 있으며, 약간의 전송 지연은 시스템 전체에 큰 영향을 주지 않으므로 보통 우선순위로 설정했습니다.

3. 태스크 구현

- StartSensorTask (실시간 데이터 생산자)

    - osDelayUntil()을 사용하여 10ms의 고정 주기로 정밀하게 동작합니다.

    - 주기마다 깨어나 Update_Motor_RPM(), Ultrasonic_Trigger() 등을 호출하여 모든 센서 값을 최신 상태로 갱신합니다.

    - 수집된 모든 데이터를 SensorData_t 구조체로 패키징하여 CANTxQueueHandle을 통해 CANTask에 전달합니다.

```c
void StartSensorTask(void *argument)
{
  // ...
  uint32_t last_wake_time = osKernelGetTickCount();
  for(;;)
  {
    // 1. 10ms 주기를 정밀하게 유지
    last_wake_time += 10;
    osDelayUntil(last_wake_time);

    // 2. 모든 센서 데이터 수집 및 갱신
    Update_Motor_RPM();
    Ultrasonic_Trigger();

    // 3. 데이터 패킷 생성
    SensorData_t sensor_packet;
    sensor_packet.rpm = MotorControl_GetRPM();
    // ... (초음파, 조도 센서 값 패키징)

    // 4. 생성된 데이터를 CANTask로 전송
    osMessageQueuePut(CANTxQueueHandle, &sensor_packet, 0, 0);
  }
}
```

- StartCANTask (데이터 가공 및 전송 컨트롤러)

    - osMessageQueueGet()을 통해 CANTxQueueHandle에 새로운 데이터가 들어올 때까지 무한정 대기합니다 (이벤트 기반 동작).

    - 데이터 수신 즉시, CAN 프로토콜에 맞게 데이터를 가공합니다. (e.g., 거리->장애물 상태 비트마스크, RPM->2바이트 정수 분리)

    - 최종 가공된 데이터를 TxData 버퍼에 채우고 CAN_Send()를 호출하여 전송을 완료합니다.

```c
void StartCANTask(void *argument)
{
    // ...
    SensorData_t received_packet;
    for(;;)
    {
        // 1. CANTxQueue에서 데이터 수신 대기
        if (osMessageQueueGet(CANTxQueueHandle, &received_packet, NULL, osWaitForever) == osOK)
        {
            // 2. 수신된 데이터를 CAN 형식에 맞게 가공
            uint8_t obstacle_status = 0;
            if (received_packet.distance_front <= 10) obstacle_status |= (1 << 0);
            if (received_packet.distance_rear <= 10) obstacle_status |= (1 << 1);
            TxData[0] = obstacle_status;

            uint16_t rpm_value = (uint16_t)received_packet.rpm;
            TxData[2] = (uint8_t)(rpm_value & 0x00FF);
            TxData[3] = (uint8_t)((rpm_value >> 8) & 0x00FF);

            // 3. 최종 데이터를 CAN 버스로 전송
            CAN_Send();
        }
    }
}
```
